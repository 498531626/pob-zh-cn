# 计算明细动态文本汉化与防回归

此前的覆盖检查只统计固定标题，运行时才从内部键名生成的“属性”列不在统计内。
`EnemyCurseLimit`、`ColdResistMax` 因此一直能够从检查中漏过。
首次对当前 `CalcSections` 实际 Lua 表扫描发现 728 个属性键，其中 564 个格式化名称未翻译。

现在按三层收集并验证：

1. 执行当前 `CalcSections.lua`，展开全部 `modName` 表，包括公共列表引用。
2. 扫描当前源码的完整字面量修正构造器，并合入运行时实际创建的属性键。
3. 用真实 `CalcBreakdownControl` 生成 12 类技能构筑的明细表，读取属性、标签、
   条件、来源及来源合计 Tooltip；为所有运行时／页面属性键补充合计提示测试。

当前合并清单为 2,249 项；运行时包含 1,347 个唯一属性键。实际表格和提示共检查
3,418 条文本，剩余英文为 0。12 类技能覆盖攻击、法术、持续伤害、召唤物和图腾；
中英文计算结果作了 15,924 次数值对比，全部一致。

## 显示实现

- `calc-identifier-terms.json`：可编辑的完整短语与组合术语，包括伤害转换、承伤、
  抗性、资源、诅咒、异常状态、逻辑条件和数量。内部属性名采用源码语义直译／组合，
  不将其宣称为游戏官方译名。完整已核对的 UI、技能译名优先使用既有词典。
- `calc_identifier_locale.py`：生成 `CalcIdentifiers.lua` 与 `CalcIdentifierTerms.lua`。
  已知短语必须完整匹配；未识别的组成部分导致生成验证失败。生成时保留数字。
- `Localization.lua`：在显示层查找动态属性名称，并翻译有限的条件／合计表达式。
  原有物品、技能及数字模板优先；不对任意用户文本做逐词替换。
- `build_locale.py`：接入属性覆盖检查和生成，新汉字同时进入字库生成流程。
- `calc-runtime-identifiers.json`：隔离运行生成的属性清单；每次实际审计刷新。
- `calc-identifier-coverage.json` 与 `calc-breakdown-audit.json`：覆盖报告、未覆盖项、
  来源文件哈希与可复查的中英文结果。

内部 `mod.name`、计算输入、数据键、用户构筑和保存格式不变。英文模式使用原文。
数字、运算符、百分号、颜色及未知文本回退均有专项检查。额外回归还覆盖了原有
物品模板、导入词条、搜索、输入、界面消息和布局，防止扩大规则时破坏既有汉化。

## 一键验证

```powershell
python tools/localization/check_calc_localization.py
```

命令自动创建并清理临时副本，不复制用户构筑、设置或语言选择。任何源码属性漏译、
实际明细残留英文、字形缺失、数字变化或已有专项检查失败都会以非零退出码结束。
这条命令已加入本项目 `AGENTS.md` 的计算页／显示层／上游更新验收要求。

新增词条时修改输入，再运行 `python tools/localization/build_locale.py` 生成资源，
最后重新运行上述一键验证。不要直接修改生成的 Lua 字典或通过放宽审计来消除失败。

## 验证边界

原生窗口使用独立副本，通过真实明细控件抽查了诅咒上限、抗性、承伤转换、图腾、
能量球和条件说明，中文与字形正常。之后用户按物理 Escape 中止了进一步界面操作。
4,214 组宽度、8 页两种分辨率、语言切换、计算及技能序列化由隔离无窗口检查验证。

构造器清单中 `EnableSkill` 有一个尚未实例化的 `skillNameList` 模板，无法直接作为
已计算单行修正绘制；报告单列该模板，未将其伪装为实际 UI 验收通过。实际构筑表格
生成没有跳过异常。覆盖范围是当前源码清单与上述构筑，未来上游新增动态组合仍由
清单、运行时审计及相应构筑扩展检查；这不等于枚举所有历史物品和任意用户构筑。
